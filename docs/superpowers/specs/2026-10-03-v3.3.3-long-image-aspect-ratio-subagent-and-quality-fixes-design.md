# v3.3.3 长图高清渲染、图片高度缓存自愈、子代理拉动思考深度与系统性质量修复设计规范

## 1. 背景与目标 (Context & Objectives)
在 v3.3.2 完成闹钟工具、应用图标快捷方式与工作区进度条后，本次攻坚针对系统深层体验缺陷与长期技术债务展开全方位闭环治理：
1. **长图模糊彻底根治**：修复长图在直接贴出预览（列表）与点开大图预览（全屏查看器）中肉眼可见模糊的严重缺陷；
2. **图片高度缓存失效自愈与错误态**：解决失效 URL 仍命中古董高度缓存导致的幽灵超高占位与布局崩塌，补齐优雅错误降级与重试交互；
3. **子代理系统升级与链路打通**：
   - UI 接入类似聊天主页的「拉动换思考深度」步进滑块组件，支持继承主助手与实时平滑拖拽档位；
   - 彻底修复 `SubAgentRuntime` 中子代理配置的 `effort` 被静默丢弃、写死主助手配置的底层断层；
   - 区分技能内置 Agent 与自定义 Agent，修复技能 Agent 删除无响应问题，补齐命名合法性校验；
4. **第一梯队核心体验**：
   - 根治语义搜索长达两个月的“乱召回”排序硬伤，恢复 RRF 倒数排名融合得分，杜绝按日期粗暴覆盖；
   - 全面推广输入框本地 Draft + 500ms 防抖，根除内置 Prompt 与网络设置中的打字跳光标；
   - 自定义应用图标规范收敛至 `images/`，自动纳入全局备份与跨机恢复；
5. **第二梯队工作区与代码健壮性**：
   - 工作区 `glob` 增加按修改时间（mtime）倒序排序，避免新文件被遍历顺序淹没；
   - 工作区 `grep` 补齐 Claude Code 参数（`-i` 大小写忽略、`output_mode` 等）；
   - 封堵 `TTS.kt` 协程泄漏，为 `ProotShellRunner` 静态闭包增加 `@Volatile`，收敛 `withSingleKey`。

## 2. 详细技术方案 (Detailed Technical Design)

### 2.1 长图高清渲染重构
- **列表直接预览 (`ZoomableAsyncImage.kt`)**：
  - **根因**：原实现对竖长图使用了 `(screenWidth / ratio).coerceIn(screenWidth, 4096)`，并作为 Coil 的 `size(targetWidth, targetHeight)`。在 Coil 默认 `Scale.FIT` 下，高度被截断为 4096 会等比例惩罚性压缩宽度（例如 1080x12000 的长图被压缩为 368x4096），拉伸到屏幕全宽后模糊 3 倍。
  - **解法**：对于竖长图（`ratio < 1f`），在请求尺寸中只约束宽度达到屏幕物理宽度 `screenWidth`，移除对高度截断导致的等比压宽，或者指定 `precision(Precision.INEXACT)` 并优先保证横向清晰度；关闭长图在超大分辨率下的硬件位图以防 GPU 限制。
- **大图点开全屏预览 (`ImagePreviewDialog.kt`)**：
  - **根因**：`rememberAsyncImagePainter(images[index])` 直接传 URL，导致 Coil 命中了聊天列表中那张被压缩成 368px 的内存缓存小图，且未显式指定原图尺寸。
  - **解法**：构建独立的 `ImageRequest`，显式指定 `size(coil3.size.Size.ORIGINAL)`、`precision(Precision.EXACT)`、`allowHardware(false)`，彻底绕过缩略小图缓存，按 100% 原始点对点像素高清解码。

### 2.2 图片高度展示缓存自愈与错误降级
- **`ImageAspectRatioCache.kt`**：
  - 新增 `@Synchronized fun remove(model: String?)` 方法，支持单个 URL 主动逐出；
  - 在 `put` 中增加比例保护阈值：限制比例在 `0.15f .. 6.0f`，防止极端畸形数据撑爆视口。
- **`ZoomableAsyncImage.kt`**：
  - 维护本地 `hasError` 状态；
  - 在 `onError` 回调中：立刻调用 `ImageAspectRatioCache.remove(model)` 并置空本地 `cachedAspectRatio = null`，彻底释放幽灵高度绑定；
  - 加载失败时渲染精致的错误占位卡片（固定高度约 80dp，显示弱化图表与微字提示），支持点击重试。

### 2.3 子代理拉动思考深度与全链路打通
- **UI 滑块重构 (`AgentDetailPage.kt`)**：
  - 移除 `ExposedDropdownMenuBox` 原生下拉框；
  - 接入 `ReasoningPicker` 风格的连续/步进 Slider 滑块组件；
  - 提供“继承主助手”（null）开关，开启时跟随主助手；关闭时展示从 OFF、LOW、MEDIUM、HIGH、XHIGH 到 MAX 的步进滑块，左右拖拽联动专属图标与档位文字。
- **运行时透传打通 (`SubAgentTool.kt` & `SubAgentRuntime.kt`)**：
  - 在 `SubAgentTool` 调用 `runtime.executeAsync / executeSync` 时透传 `agentDef.effort`；
  - 在 `SubAgentRuntime` 构建 `TextGenerationParams` 时，若 `agentEffort` 不为空，转换为对应的 `ReasoningLevel` 赋给 `params.reasoningLevel`，真正生效！
- **技能 Agent 区分与命名校验 (`SubAgentsPage.kt` & `AgentDetailPage.kt`)**：
  - 在列表页为来自技能的 Agent 打上 `[技能内置]` 标识 Chip，隐藏其删除菜单；
  - 新建 Agent 时，增加正则校验 `^[a-zA-Z0-9_-]+$`，杜绝非法路径字符。

### 2.4 第一梯队：语义搜索乱召回与全量输入防抖
- **语义搜索乱召回修复 (`ConversationRepository.kt`)**：
  - 移除 `searchConversationMessages` 与 `searchConversationMessagesAll` 中粗暴覆盖 RRF 综合分数的 `.sortedByDescending { it.date }`；
  - 默认严格按 RRF 倒数排名融合得分降序输出，确保最相关的消息排在第一位。
- **全局输入框防抖与状态反流根治**：
  - `SettingModelPromptPage.kt`：对 5 项内置 Prompt 建立本地同步 Draft 状态，配合 500ms `LaunchedEffect` 防抖异步落盘；
  - `SettingPreferencesNetworkPage.kt`：对 `userAgent` 建立本地同步 Draft 状态与 500ms 防抖落盘；
  - `AssistantPromptPage.kt`：在 `snapshotFlow { systemPromptValue.text }` 增加 `.debounce(500)`，避免每次击键都产生 SQLite 写入。
- **应用图标自动备份 (`SettingPreferencesAppIconPage.kt`)**：
  - 图标存储路径收敛至 `context.filesDir/images/custom_app_icon.png`，自动继承 `BackupManager` 的备份覆盖。

### 2.5 第二梯队：工作区强化与代码健壮性
- **工作区 `glob` mtime 排序 (`WorkspaceFileSystem.kt`)**：
  - 在过滤出匹配文件后，先按 `file.lastModified()` 降序排序，再执行 `take(config.maxListEntries)`；
- **工作区 `grep` 补齐参数 (`WorkspaceTools.kt`)**：
  - 增加 `ignore_case`（默认 true）、`output_mode`（`"content" | "files_with_matches" | "count"`）、`head_limit` 参数支持；
- **并发与泄露修复**：
  - `TTS.kt`：为 `CustomTtsStateImpl` 作用域绑定 `SupervisorJob()` 并在 `cleanup()` 中执行 `scope.cancel()`；
  - `ProotShellRunner.kt`：为 `extraEnvProvider` 标注 `@Volatile`；
  - `SearchService.kt`：收敛 `withSingleKey` 的 `else -> this` 盲区。
