## 1. 本会话核心攻坚与突破全景

### A. 大图预览长图模糊根治（修复用户点开发图全屏预览模糊问题）
- **现象**：用户发送的高清长截图，点开全屏大图预览时呈现严重的低模模糊和像素拉伸马赛克。
- **全链路根因剖析**：
  1. **Coil 内存缓存严重污染**：聊天气泡缩略图（`MessageImageThumb`）为了展示小图，使用了 `height(72.dp)`，Coil 将长图高度下采样至约 150px 生成极低清小位图并存入了全局内存缓存。大图查看器在向 Coil 请求同一 URL 时，未禁用内存缓存读取，Coil 直接取出了 150px 高的极小缩略图拉大到全屏展示；
  2. **首帧 1024x1024 伪尺寸陷阱**：大图查看器在首帧异步解码未就绪时，原先代码粗暴将尺寸兜底为 `Size(1024f, 1024f)` 正方形。手势缩放库在首帧根据正方形初始化了坐标系和缩放容器，长图到达后未重新计算变换树，导致严重失真。
- **治理落地**：
  1. 在 `ImagePreviewDialog.kt` 的 `ImageRequest.Builder` 中加入 `.memoryCachePolicy(coil3.request.CachePolicy.WRITE_ONLY)`，禁止读取气泡生成的低清缓存，强制直接从本地存储的物理原图进行全分辨率、无损原画的高精度重新解码；
  2. 增加 `resolveSynchronousImageSize` 函数，通过 `BitmapFactory.Options(inJustDecodeBounds = true)` 在第 0 毫秒瞬间读取本地物理文件的绝对真实宽高（例如 1080 × 8500），消除伪尺寸失真拉伸。

### B. 行内公式排版纯净化与长按文本复制 100% 恢复
- **决断与切除**：
  - 在 Compose 的 `Text` 内部，`InlineTextContent` 是一个嵌在文本流里的原子插槽，强行在里面塞入滚动容器和指针拦截，不仅破坏了 Compose 文本引擎原本自然的字流折行，更严重的是直接截胡了触控手势，导致外层 `SelectionContainer` 彻底丧失了长按文本选择与复制的能力；
  - 彻底切除了 `formulaScrollable`、`horizontalScroll` 与 `DisableSelection`；
  - 恢复纯净物理占位符宽度（`with(density) { m.widthPx.toSp() }`），公式紧随文本流自然折行，彻底消除前缀被挤下行引发的悬空大空行；
  - 气泡外层 `SelectionContainer` 重新无缝接管全文，**长按呼出复制菜单、拖动光标选区完全恢复原生体验**。
- **纯粹保留顶层排版精修**：
  - 对称式半高扩展基线对齐算法（文本等号 `=` 与分式横线像素级绝对共线，分母留足间隙绝不压盖下行）；
  - 列表项圈符基线穿透（`propagateFirstBaseline`）；
  - `LatexSplitter` 与 `LatexText` 针对 `♀`、`♂` 等特殊符号的容错清洗与自动重试机制；
  - 补充针对 `♀`、`♂` 生物学公式的白盒切分自动化单元测试套件（`ComprehensiveOptimizationsEffectivenessTest.kt`）。

### C. 桌面快捷方式权限引导与系统设置直达
- **背景痛点**：
  - 之前的自定义图标功能通过 `ShortcutManagerCompat.requestPinShortcut` 发送桌面快捷方式；
  - 但国内厂商系统（MIUI/HyperOS、ColorOS、OriginOS、EMUI/MagicOS 等）默认将「创建桌面快捷方式」权限设置为“禁止”且静默丢弃，导致用户裁切图片点击生成后桌面上没有任何反应。
- **治理落地**：
  1. 在 `SettingPreferencesAppIconPage.kt` 增加了 `showPermissionGuideDialog` 引导弹窗，在发起创建请求后向用户明确说明可能被系统静默拦截；
  2. 实现 `openAppShortcutPermissionSettings(context)`，按厂商优先级自动精准跳转小米/华为/OPPO/vivo系统专属应用权限页，并安全回退到标准系统设置详情页；
  3. 设置页中新增「开启桌面快捷方式权限」操作条目，支持一键直达系统设置。

### D. 图片全链路 8000px 阈值与 GPU 双线性平滑缩放
- **单边硬门禁放宽至 8000px**，完美贴合各大模型（尤其 Claude 8000px）红线，同时杜绝了 16000px 极端大图的 1GB 内存 OOM 隐患；
- 引入以目标尺寸为下限的预采样配合 GPU 双线性插值平滑缩放，彻底消灭长图短边被粗暴除以 4/8 腰斩至 270px 的模糊问题；
- 识图工具 `read_image` 规格放宽至 48MB / 16 张 / 45s 超时。

### E. Termux 级保活与 Android 14+ 崩溃根除
- `KeepAliveService` 切换为 `specialUse` 类型，彻底消除 6 小时强制超时抛出的 `ForegroundServiceDidNotStopInTimeException` 强杀崩溃；
- 引入类似 Termux 的 CPU 唤醒锁 `PARTIAL_WAKE_LOCK`，防止息屏时 CPU 休眠冻结进程；
- Android 14 (API 34) 模拟器实测 dumpsys 验证 100% 正常生效（`types=40000000 (specialUse)` 与 `mHoldingWakeLockSuspendBlocker=true`）。
