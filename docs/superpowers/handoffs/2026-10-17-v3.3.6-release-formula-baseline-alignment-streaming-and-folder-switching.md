## 一、 本阶段战役核心攻坚与交付成果

本阶段聚焦攻坚复杂的数学公式与列表圈符垂直几何对齐、溢出公式滑动交互与手势冲突根除、流式出字顿挫感治理、引用语法多目标扩容与侧边栏文件夹快速切换能力：

### 1. 行内公式与同行文本/符号基线绝对共线对齐（对称式高度扩展 + TextCenter 对齐 + yOffset 位移）
- **视觉缺陷排查**：在带有文字前缀（如 `AA = ♀ A × ♂ A = `）或标点后缀的行中，公式的分数线明显漂浮在文字等号上方 5~10dp，文字沉在底端，数学轴严重脱节不共线。
- **底层根因分析**：v3.3.5 为了解决压盖下一行，将深度公式切换为 `PlaceholderVerticalAlign.Center`。然而 Compose 的 `Center` 将公式包围盒的中心对齐到了**整行的垂直中心**；当公式由于分式变高（如 40dp）时，整行被撑开，文字的基线被推到了行底端（距顶约 25dp），而公式分数线位于距顶 18dp 处，造成公式高高飘起、文本沉底错位。
- **创新几何算法（`Markdown.kt` + `MarkdownNew.kt`）**：
  - 利用公式上方高度 $H = m.heightPx$、下方深度 $D = m.depthPx$ 以及字体数学轴 $fontCenterPx = (ascent + descent) / 2 pprox -0.325 	imes fontSizePx$（等号 `=` 所在位置）；
  - 取对称扩展半高 $halfExtentPx = \max(H + fontCenterPx, D - fontCenterPx)$；
  - 占位符高度设为 $halfExtentPx 	imes 2$，并使用 `PlaceholderVerticalAlign.TextCenter` 对齐；
  - 内部施加精确垂直位移 $yOffsetPx = halfExtentPx - H - fontCenterPx$；
  - **效果**：公式基线与文本基线在同一个像素点上绝对重合，**文字等号 `=` 与分式分数线 `---` 100% 绝对水平共线**；同时 Compose 为下方预留的 descent 深度保证 $\ge D$，下方行距自然撑开，**彻底杜绝压盖下一行内容**！

### 2. 富文本圈符（列表项 Bullet `o`）基线穿透对齐（`propagateFirstBaseline`）
- **视觉缺陷排查**：在包含数学公式的列表项（如 `o AA = ♀ A × ♂ A = ...`）中，圈符 `o` 悬浮在第一行文字顶端上方，与下方的公式完全错位脱节。
- **底层根因分析**：`ListItemNode` 中 `Row(verticalAlignment = Alignment.Top)` 包含左侧 `Text(bulletText)` 和右侧内容 `Box { Column { MarkdownNode ... } }`。当右侧第一行包含大分式公式撑高整行时，文本基线位于靠下位置，而左侧 `o` 作为普通小文本被 Top 对齐在最顶端，产生严重上下断层。
- **基线穿透解决方案**：
  - 定义基线穿透修饰符 `propagateFirstBaseline()`，利用 Compose 的 `Modifier.layout` 测量子级的 `FirstBaseline` 并向外透传；
  - 在 `ListItemNode` 的 `Row` 中为圈符接入 `Modifier.alignByBaseline()`；
  - 右侧内容容器 `Box`、内部 `Column` 以及 `Paragraph` 容器均挂载 `propagateFirstBaseline()`；
  - `Row` 自动将圈符 `o` 的基线与段落第一行文字/公式等号的数学基线对齐在绝对同一条水平线上，实现 100% 水平共线。

### 3. 溢出行内公式横向滑动彻底打通（手势穿透 + 智能折行 + 宽度安全钳位）
- **无法滑动的深层根因定位**：
  1. **手势拦截（核心根因）**：生成结束后气泡外层启用了 `SelectionContainer` 用于文本复制。Compose 的 `SelectionContainer` 会强行抢占内部所有横向拖拽手势用于文字框选，导致内部 `horizontalScroll` 无法收到滑动事件；
  2. **超宽判定盲区**：公式跟在较长文本后面时，两者叠加超出了屏幕边界，但公式单体宽度若未超全屏宽，导致滑动容器未被激活；
  3. **未钳位导致滑动区间为 0**：占位符若未钳位，Compose 将内部容器直接拉大到超出视口并在外层裁切，内部 `scrollState.maxValue` 判定为 0。
- **彻底根治方案**：
  - 在横向滑动 `Box` 外层包裹 `DisableSelection { ... }`，屏蔽文本选择手势抢占，让拖拽手势 100% 传递给公式滑动；
  - 在公式前插入隐形换行锚点 `append("​")`（ZWSP），当同行前置文本过长时自动智能折行，消灭被同行文本强挤出右边界的现象；
  - 占位符宽度安全钳位至 `maxWidthPx`，并在超宽时由 `horizontalScroll` 赋能用户左右自由滑动查看超长分式每一个字符。

### 4. 思考与正文出字流式体验质感跃升（`conflate()` 替换 `debounce(50L)`）
- **顿挫根因分析**：此前在 `MarkdownBlock.kt` 与 `MarkdownNew.kt` 中使用了 `debounce(50L)`。在 LLM 持续吐字（每 20~40ms 一个 token）期间，每个新 token 都会不断重置 50ms 定时器，导致流式吐字期间界面被强行冻结不出字，直到模型停顿或生成完毕才突然喷出一大坨。
- **精准优化**：彻底移除 `debounce(50L)`，改用高吞吐低延迟的 `conflate().map { parseMarkdownCached(it) }` 流管道。首字 0ms 闪现呈现，流式吐字期间后台协程按实际最高帧率（30~60fps）实时更新，打字机如行云流水般自然流淌。

### 5. 思考折叠预览态实时滚动跟随（`verticalScroll(enabled = false)` + `scrollTo(maxValue)`）
- **盲裁切根因分析**：v3.3.4 为消除折叠态手势冲突移除了 `verticalScroll`，导致 `scrollState` 与内部内容解绑，流式吐字期间 100dp 预览框无滚动能力，只展示最初生成的 100dp 旧文本，后续新字全被静默裁剪在下方。
- **精准优化**：在折叠预览态 Column 上重新挂载 `.verticalScroll(state = scrollState, enabled = false)`，`enabled = false` 确保用户滑动手势 100% 穿透外层列表零断触；流式生成期间调用 `scrollState.scrollTo(scrollState.maxValue)` 实时吸底平滑展示最新思考行。

### 6. 引用语法深度扩容（`[citation:03c0ba]` 与多目标 `[citation:...,...]`）与原版胶囊样式复原（高度 1.1em）
- **多目标引用解析**：引入 `CITATION_MULTI_REGEX`，支持匹配以逗号、分号或空格分隔的多个引用短 ID（如 `[citation:03c0ba,1a2b3c]`），在预处理阶段自动展开为独立的标准引用流并渲染为多个独立胶囊；
- **放宽 ID 限制**：移除旧版 `id.length == 6` 的硬编码门禁，改为 `id.isNotEmpty()`；
- **原版视觉样式复原**：胶囊高度精准微调为 1.1em，恢复原版 Thin 极细字重与 0.2f 浅淡背景，移除了文字内部水平 padding；
- **交互能力保留**：点击任一胶囊即可调起系统浏览器直达对应来源链接。

### 7. 对话序列视图跳转定位修复（常驻式容器 + 弹底守卫 `hasAutoScrolledToBottom`）
- **重构模式切换**：`ChatList` 模式切换重构为 `Box` 底层保持 `ChatListNormal` 常驻，外层覆盖 `AnimatedVisibility` 浮现 `ChatListPreview`，避免切换时主列表树被卸载销毁；
- **弹底守卫防护**：引入 `hasAutoScrolledToBottom` 保护守卫，严格限制仅在真实初次打开会话时执行一次遮罩弹底；
- **定位稳固**：点击跳转时，`state.requestScrollToItem(index)` 精确命中目标消息，视口稳如泰山。

### 8. 侧边栏文件夹管理交互升级（选中态再次点击竖排列出所有文件夹一键切换）
- **交互增强**：在 `ChatDrawer.kt` 的 `FolderBar` 中，当某个文件夹已被选中后（包括“默认”会话或自定义文件夹），**再次点击该文件夹 Chip**：
- 自动弹出一个整洁优雅的竖向下拉菜单（`DropdownMenu`），依序列出默认会话及当前已有全部文件夹，当前选中项右侧标注 `HugeIcons.Tick01` 勾选图标；
- 点击任意一项立即秒切对应文件夹，并在自定义文件夹菜单底部保留了“重命名”与“删除”快捷入口。
